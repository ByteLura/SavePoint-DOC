API reference

Namespace: ByteLura.SavePointPro. Everything your game calls is static on SavePoint and SaveProfiles, plus two components (SavePointAutosave, SaveSlotPanel).

SavePoint

Settings and profiles

  • SavePointSettings Settings { get; } — the active settings. Found automatically in a Resources folder, or handed over with SavePoint.Configure(settings).
  • string ActiveProfileId { get; } — the profile saves go to. The first profile is created for you ("Player 1") if none exists.
  • void SetActiveProfile(string profileId)
  • SaveData NewData() — fresh data stamped with the current data version.
  • int CurrentDataVersion { get; }

Saving and loading

  • SaveResult Save(int slot, SaveData data, string summary = null) — slots are 0 to 9. The summary is the line your players see on the slot screen.
  • SaveResult SaveNamed(string slotName, SaveData data, string summary = null) — saves to the slot with that name, creating it in the first free slot.
  • LoadResult Load(int slot) / LoadResult LoadNamed(string slotName)
  • bool SlotExists(int slot)
  • SlotMetadata GetSlotMetadata(int slot) — null when the slot is empty.
  • IReadOnlyList<SlotMetadata> ListSlots(string profileId)
  • SaveResult DeleteSlot(int slot) — removes the file and its backups.
  • void Checkpoint(string checkpointName, SaveData data) — writes to the same-named checkpoint slot, or the first free slot.

Migration and custom types

  • void RegisterMigration(int fromVersion, Action<SaveData> step) — one upgrade step, fromVersion to fromVersion + 1. Register at startup, before any load. See the migration guide.
  • void RegisterSerializer<T>(Func<T, string> to, Func<string, T> from) — custom text serializer used by SaveData.SetObject/GetObject for that type, in place of JSON.

Cloud

  • ISaveCloudProvider CloudProvider { get; set; } — your provider, or the shipped MockCloudProvider. Null means local only.
  • SaveCloudSync.SyncSlotAsync(profileId, slot) — newest-wins sync of one slot; SaveCloudSync.OnConflict decides exact-tie conflicts. See the cloud sync guide.

Events

  • OnAfterSave(SaveResult), OnLoaded(LoadResult), OnSaveFailed(SaveResult) — every completed save/load reports here.
  • OnRecoveredFromBackup(SlotMetadata) — a load used a backup because the newest file failed its integrity check. A good moment to tell the player, in your own words, that their progress is safe.

SaveData

Typed key-value store. Setters: SetInt, SetLong, SetFloat, SetDouble, SetBool, SetString, SetVector2, SetVector3, SetQuaternion, SetColor, SetIntArray, SetFloatArray, SetStringArray, SetObject<T>. Getters mirror them and take a default returned when the key is missing (GetInt("coins", 0)). Also HasKey, RemoveKey, Clear, Keys (sorted), Count, Version, and PlaytimeSeconds (total seconds played; your game accumulates it, the slot screen displays it).

The same data always serializes to the same bytes, so saves can be diffed and hashed in your own tests.

SaveProfiles

  • ProfileInfo CreateProfile(string displayName) — creating an existing name returns that profile.
  • IReadOnlyList<ProfileInfo> ListProfiles()
  • ProfileInfo GetProfile(string profileId)
  • SaveResult RenameProfile(string profileId, string newName)
  • SaveResult DeleteProfile(string profileId) — removes the profile, its slot files, and their backups. Other profiles are untouched.

Types

  • ProfileInfo — Id, DisplayName, CreatedUtc.
  • SlotMetadata — SlotIndex, SlotName, ProfileId, CreatedUtc, ModifiedUtc, PlaytimeSeconds, DataVersion, Summary, IsCheckpoint, State (Occupied, RecoveredFromBackup, Unreadable).
  • SaveResult — Success, Message, Metadata. Returned by save, delete, and profile actions.
  • LoadResult — Success, Message, Data, RecoveredFromBackup, NewerVersion (the save came from a newer build of your game; it was loaded without changes).
  • SaveMigrationException — carries FromVersion and ToVersion. Load catches it and reports the gap as a LoadResult; it reaches your code only if you drive the chain yourself.

Components

SavePointAutosave

Fields: SlotIndex, IntervalSeconds (0 disables the interval), SaveOnPause, SaveOnQuit, SaveOnSceneChange, and Data — the SaveData it keeps saved. OnAutosaved(SaveResult) fires after each attempt.

SaveSlotPanel

Add to a Canvas; it builds its own interface: profile header with a switcher, the ten slot cards, and Save / Load / Delete / New Game actions with a two-step delete confirm. Events OnSaveRequested, OnLoadRequested, OnDeleteRequested, OnNewGameRequested carry the slot index. For zero-code use, set ActDirectly (on by default) and a DataProvider (Func<int, SaveData>): loads and deletes then work with no game code, and LastLoadedData holds the last loaded save. When you subscribe to an event yourself, that action is yours.

SavePointSettings

Created by Setup in a Resources folder. Fields: EnableEncryption (on by default), DeveloperKey, BackupCount (1-5, default 3), Format (Json or Binary), RootFolderOverride (empty means the default per-user save folder), CurrentDataVersion. Edit it in the home window's Settings tab.

Storage seam

ISaveStorage (Exists, Read, WriteAtomic, Delete, List) is the seam under everything; FileSaveStorage is the shipped implementation. Advanced projects can substitute their own storage by implementing the interface — every guarantee in this package (atomic writes, backups, recovery) is expressed through it.
