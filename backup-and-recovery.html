Backup and recovery

A bad shutdown mid-write is the classic way players lose saves. SavePoint Pro writes so that a crash at any point leaves the last good save intact.

The write path

Every write is atomic:

  1. Serialize the envelope.
  2. Write it to <file>.tmp and flush.
  3. Rotate backups — .bak1 … .bak3 (the count is configurable, 1–5).
  4. Replace the primary file with the new write.

At no point is the only good copy overwritten by unverified bytes.

The read path

Every read verifies the envelope's SHA-256 checksum. On failure the loader walks the backup chain newest-first and returns the first copy that verifies, raising OnRecoveredFromBackup. If every copy is damaged, the load fails clean with a plain-language result — and the files are preserved on disk, never silently wiped, so support can still look at them.

What this is tested against

The diagnostics self-check in the editor window exercises this exact machinery on demand: it writes an encrypted save in a temp folder, deliberately damages the primary, and recovers from backup — reporting each step. Run it any time from SavePoint Pro Home > Diagnostics > Run Self-Check.
