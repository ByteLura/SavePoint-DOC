What version 1 is not

An honest list, so you can decide with the full picture.

  • Not a cloud service. Sync is an interface plus a local mock. No platform provider (Steam, PlayFab, console, or any other) ships in the box; you implement the four-method interface against your own backend.
  • Not a save editor. The editor window browses slot metadata and deletes slots. It does not open or edit the contents of a save.
  • No compression. Save files are as large as the data in them. The binary format is compact framing, not compression.
  • No save merging. When two copies of a slot diverge, sync picks the newer one (or asks your conflict handler). It never merges fields.
  • No visual conflict resolution. Exact-tie conflicts are reported through the conflict callback, not a dialog.
  • No cross-product import. SavePoint Pro reads its own files only. It does not import saves written by other save products.
  • One UI flavour. The slot screen is uGUI, built in code, in one neutral dark theme you can recolour. There is no TextMeshPro variant in version 1.
  • Single-device authority. Saves live on the device; the cloud interface moves whole files. This is not a multiplayer or server-authoritative save system.
  • Console note. No console SDK code ships. On console, the storage and cloud interfaces are yours to implement against the platform SDK; everything above them works the same.

Support

Support: bytelura@gmail.com. Write to that address — keeping one support door means nothing gets lost between inboxes.

Before you write, run the self-check (SavePoint Pro Home > Diagnostics > Run Self-Check) and include its six step results, your Unity version (2022.3 LTS or Unity 6), the SavePoint Pro version, and the exact result message the API returned. Support will never ask for your developer key or your players' save files — never send either.
