Saving from your game

The everyday calls

  • SavePoint.NewData() — a fresh SaveData with the current data version stamped.
  • SavePoint.Save(slot, data, summary) — writes a slot of the active profile. Returns a SaveResult.
  • SavePoint.Load(slot) — returns a LoadResult with the data, after checksum verification, backup recovery if needed, and migration if the file is older than the current data version.
  • SavePoint.Checkpoint(name, data) — a named checkpoint slot.
  • SavePoint.Configure(...) — point the facade at your settings, profile, and storage.

Results, not exceptions

Expected problems come back as results with plain-language messages: an empty slot, a damaged file with no good backup, a save written by a newer build of your game. The messages are written to be shown in a log or pasted into a support mail. Programming errors (a missing migration step) throw — see the migration page.

Autosave

The SavePointAutosave component saves on an interval, when the game pauses, and when the player quits. Keep its Data reference pointing at your live SaveData. In the shipped demo it runs every 20 seconds.

Events

The facade raises events around saves and loads, including OnRecoveredFromBackup when a read had to walk the backup chain — the hook to use if your game wants to tell the player their save was recovered rather than lost.
