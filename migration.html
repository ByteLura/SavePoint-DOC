Versioned migration

Games update; saves must not break when they do. Every save carries a data version (an int, starting at 1). The current version is a Settings value you bump when your data shape changes.

Registering steps

SavePoint.RegisterMigration(1, data =>
{
    // v1 -> v2: coins moved under a wallet object
    int coins = data.GetInt("coins");
    data.SetInt("wallet.coins", coins);
});

What happens on load

If a file's version is below current, the registered steps apply in ascending order to an in-memory copy. The upgraded save is written back atomically only after the whole chain succeeds.

The safety rules

  • A missing step throws SaveMigrationException, and the original file stays byte-identical — a failed upgrade never half-writes.
  • Migration happens before your game sees the data, so game code only ever reads the current version.
  • The diagnostics self-check runs a two-step version upgrade against a v1 fixture, so you can watch the chain work before trusting it with player saves.

Read this page before you bump the data version in a shipped update: the one thing migration cannot do is invent a step you did not write.
