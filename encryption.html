Encryption

Save files are encrypted with AES-256 over the envelope payload. Encryption is on by default; it is a Settings toggle, and the envelope flag records whether a given file is encrypted.

  • The key is derived from the developer key string in your Settings asset via PBKDF2 with 100,000 iterations.
  • Every write uses a fresh random salt and IV, stored in the file header.
  • Set your own developer key before you ship, and treat it like a password: anyone who has it can open your saves.

What a wrong key does

A wrong key or a tampered ciphertext fails the checksum/decrypt step cleanly and falls into the backup chain — exactly like a corrupted file. You never get a partial or garbled load: either the data verifies and loads, or the recovery walk takes over, or the load result explains the failure in plain language.

Encryption protects save files at rest on the player's machine. It is not DRM and does not stop a determined owner of the machine from extracting the key from a shipped build — no client-side scheme can. What it does stop is casual save editing and file sharing of saves.
